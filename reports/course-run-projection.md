# 講座進行の想定（この資料一式で実際にどう進むか）

`01-curriculum.md`（カリキュラム）・`04-guidance.md`（1 日の流れ）・`05-instructor-guide.md`
（講師運用）・`06-rolling-operations.md`（ローリング入学）・`07-exam-phase.md`（試験対策）・
`08-personas.md`（受講者像）・`reports/persona-simulation-2026-07.md`（受講シミュレーション）
から導いた、**実際の進行の想定**。数値は設計値と推定値であり、初回コホートの実測で較正する。

## 0. 前提（この講座の性格）

| 項目 | 内容 |
|---|---|
| 対象 | **IT リテラシーゼロの成人**（中心層＝ペルソナ「佐藤さん」23 歳・完全未経験） |
| 進め方 | **自習型**。講師の一斉講義は行わない。受講者が教材を自分で読み、講師は**レビュー役** |
| 入学 | **ローリング型**（随時入学）。受講者ごとに進度が異なる |
| 1 日 | 7 時間 × 5 営業日 / LESSON |
| ゴール | 修了ではなく **CCNA 200-301 合格** |

---

## 1. 全体のタイムライン

```
LESSON0（5日）        LESSON1〜4（20日）              試験対策（5日〜）
IT ベーシック    →    本編 Exercise1〜20        →    模試サイクル → 受験
P1〜P5                各 LESSON の最後にまとめテスト   GO 判定 → 予約 → 受験 = 卒業
                      Exercise20 で修了テスト
```

**設計上は 25 営業日 + 対策 5 日 = 30 営業日。**
ただしシミュレーションでは、中心層（佐藤さん）の**実所要は約 50 営業日（2.5 ヶ月）**。
差の 20 日は「再テスト・つまずきの補強・対策フェーズの延長」で、**これは想定内の姿**。

| 受講者像 | GO 到達 | 合格までの総所要 | 初回合格率 | 再受験込み |
|---|---|---|---|---|
| 佐藤（完全未経験・中心層） | 39 営業日 | **約 50 営業日** | 55% | 88% |
| 田中（異業種転職・34 歳） | 37 営業日 | 約 45 営業日 | 55% | 88% |
| 鈴木（半歩経験者・LESSON0 省略） | 33 営業日 | 約 35 営業日 | 68% | 90% |

> **コスト計画は「佐藤さんの 50 営業日」を基準に置く**のが現実的。
> 30 日で終わる前提を置くと、ほぼ確実に破綻する。

## 2. 1 日の流れ（毎日これの繰り返し）

| 時間 | 内容 | Backlog 課題 |
|---|---|---|
| 9:00〜9:30 | **振り返り**: 前 Exercise の解答解説確認 → 誤答ノート解き直し → ウォームアップ想起クイズ | 前 Exercise の小テスト課題 |
| 9:30〜13:00 | **自習**（教材を読む・3.5h）。最後の 5 分で白紙に要点を書き出す | `[ExerciseNN] 講義` |
| 13:00〜14:00 | 昼休み | — |
| 14:00〜16:30 | **ラボ演習**（Packet Tracer・2.5h） | `[ExerciseNN] ラボ` |
| 16:30〜17:30 | **小テスト**（30〜40 分）→ 誤答ノートに記録 | `[ExerciseNN] 小テスト` |

**講師側の 1 日**: 9:00 に解答解説を公開＋再テスト課題の発行 → 日中は質問に**1 時間以内**で
一次回答 → 夕方に提出物の確認。受講者 1〜3 名なら **30〜60 分/日**、4〜8 名で **1〜2.5 時間/日**。

## 3. LESSON ごとの進行と、そこで起きること

### LESSON0（P1〜P5・5 日）— IT の土台をつくる

| Exercise | 内容 | 想定される状況 |
|---|---|---|
| P1 | コンピュータの基礎 | PC 操作から。ここで脱落する人はまず出ない |
| **P2 ☆** | **数の基礎（2進数・16進数）** | **最初の山場**。ここの理解度がサブネット計算に直結する |
| P3 ☆ | インターネットの基礎 | 「動いていた仕組み」が言語化される回。手応えが出やすい |
| P4 | 仕事の IT 基礎（Backlog・Markdown） | 以降毎日使う道具の練習。実質ガイダンスの実践編 |
| P5 | ネットワークに触れる（ipconfig・PT） | **早期勝利**: 自分の手で `ping` が通る |

**この 5 日の目的は知識よりも「動いた」体験と学習習慣**。P5 で ping が通った時点で、
「自分にもできそう」という感触を作れているかが、以降の完走率を大きく左右する。

### LESSON1（Exercise1〜5）— ネットワークの言葉を覚える

OSI / TCP-IP → IOS 操作 → **IPv4 とサブネット** → IPv6 → TCP-UDP・物理層。

- **Exercise3（サブネット）が最初の本格的な壁**。シミュレーションでは
  **まとめテスト①でサブネット計算の失点が全ペルソナで発生**。
- ここから**計算ドリル**（2進数 → サブネット → ワイルドカード）を毎朝 5 問の常設運用にする。
- Exercise5 のまとめテストで 70% を切る受講者が出るのは想定内。補講 → 再テストで次へ。

### LESSON2（Exercise6〜10）— スイッチを触る

VLAN → トランク → VLAN 間ルーティング → STP / EtherChannel → 無線 LAN。

- 手を動かす実感が戻る区間で、比較的つまずきにくい。
- Exercise9（STP）と Exercise10（無線・WLC GUI）はラボの難度が上がる。
- **LESSON2 のうちに「次が最難関」と予告しておく**（山場の正常化）。

### LESSON3（Exercise11〜15）— **最難関**

静的ルート → OSPF → OSPF 応用・FHRP → NAT → IP サービス総合。

- **シミュレーションでは全ペルソナが再テスト多発**。認知負荷が最も高い。
- 「つまずくのが普通」と事前に伝えてあるかどうかで、離脱するか踏みとどまるかが分かれる。
- **補強日／余白をあらかじめ確保**し、ラボの一部を宿題化できる前提で運用する。
- 越えたら明確に区切って承認する（ここを越えると完走率が跳ね上がる）。

### LESSON4（Exercise16〜20）— 仕上げ

セキュリティ概念 → ACL → L2 セキュリティ・VPN → 自動化 → 総復習・修了テスト。

- Exercise17（ACL）は教材の完成度が最も高い区間で、比較的スムーズ。
- **Exercise20 で修了テスト（60 問 / 90 分・75% 合格）＋総合演習ラボ**。
- シミュレーションでは**全ペルソナが修了テストを初回 72〜74% で落として +2 日**。
  これも想定内として補講 → 再テストの枠を見込んでおく。

## 4. 試験対策フェーズ（Exercise21〜・標準 5 日）

修了後に自習期間は設けず、**そのまま研修の一部として模試サイクルを回す**。

| Exercise | 午前 | 午後 |
|---|---|---|
| 21 | 本試験オリエン（形式・時間配分・Sim の解き順）→ **模試①** | 誤答分析・弱点ドメイン 2 つ特定 |
| 22 | 弱点ドメイン①の補強 | 弱点ドメイン②の補強＋苦手ラボやり直し |
| 23 | **模試②** | 誤答分析＋誤答ノート総ざらい |
| 24 | 残弱点の補強＋暗記事項の最終確認 | 総仕上げラボ（制限時間つき） |
| 25 | **模試③（最終判定）** | GO 判定 → 受験予約／未達なら延長 |

**受験 GO 基準**: 総合 85% 以上を直近 2 回連続（うち 1 回は「重い回」＝模試②④⑤）、
全 6 ドメイン 70% 以上、誤答ノートの卒業 9 割。

**想定**: 標準 5 日で GO に届く受講者は少数。シミュレーションでは**全ペルソナが +4〜5 日の延長**。
模試スコアは `62 → 71 → 79 → 84 → 86 → 88`（佐藤さん）と、**6 回目でようやく GO 水準**。
延長用に模試④⑤を用意してあるのはこのため。

受験日は**模試①で見込みが立った時点で先に予約**する（締め切り効果で仕上げが締まる）。
不合格の場合はスコアレポートのドメイン別成績で弱点を特定し、1 週間補強 → 再受験
（Cisco の再受験ルールは 5 日待機）。

## 5. 講師が実際にやること（自習型なので「教える」ではない）

| タイミング | やること |
|---|---|
| 開講前 | KPI 計測シートの準備、離脱シグナル基準の確認、キックオフ面談 |
| 毎日 9:00 | 解答解説の公開、再テスト課題の発行、誤答ノート更新の確認 |
| 日中 | 質問に 1 時間以内で一次回答（**答えを言わず、切り分けの筋道を返す**） |
| 夕方 | 提出物（`.pkt`・スクショ・コメント）の確認、小テストの採点 |
| LESSON ごと | まとめテスト採点 → 個別レビュー 15 分、KPI 更新、個人スコアカード更新 |
| Exercise20 | 修了テスト採点 → 試験対策フェーズへの GO |
| 対策フェーズ | 毎日の誤答分析レビュー 15 分、GO 判定、受験結果の記録 |

**「講義をしない」ことの意味**: 講師の付加価値は説明ではなく、
(1) つまずきの早期検知、(2) 本人の気づきを引き出す個別レビュー、(3) 学習の伴走。
一斉解説をやり始めると自習型の設計が崩れるので、**個別レビューに寄せる**。

## 6. 離脱リスクと、それに対する打ち手

離脱は **序盤 3 日** と **LESSON3 の山場**に集中する。

| シグナル | 黄（要観察） | 赤（即フォロー） |
|---|---|---|
| 提出遅延 | 期限当日に未提出 | 2 営業日連続で未提出 |
| 小テスト | 1 回 70% 未満 | 2 回連続 70% 未満 |
| 質問 | 3 営業日質問ゼロ | 1 週間発話ゼロ |
| ログイン | 1 営業日なし | 2 営業日なし |

**沈黙は理解ではなく孤立のサイン。** 検知した翌営業日に講師から声をかける
（詰問せず「どこまで進んだ？」から入る）。

## 9. この想定の弱点（正直に）

- **数値はすべてシミュレーションによる推定**で、実受講者のデータではない。
  特に「初回合格率 55%」「総所要 50 営業日」は、初回コホートで大きく振れる可能性がある。
- **Exercise の学習順序**については外部レビューで再三「組み替えた方が理解しやすい」と
  指摘されており（VLAN の前にルーティング基礎、STP をより後ろへ 等）、
  現行順序は CCNA 出題ドメイン順を優先した設計。**初回コホートの実データで判断する**方針
  （`reports/material-review-response-2026-08.md` の IMP-5）。
- 自習型で「1 日 7 時間の自学」を継続できるかは受講者の生活状況に依存する。
  ローリング入学では**同期の仲間がいない**ため、孤独対策（ピア共有会）の実効性が鍵。
